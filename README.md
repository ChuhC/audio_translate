# audio_translate

一个在本机运行的音频转文字小工具，主要用于把课程、讲座等中文录音整理成文字稿，方便回看、搜索和写学习日报。

基于 faster-whisper，支持直接读取音频，也可以从 MP4 中提取音轨。转写过程中显示进度，并保存检查点，中断后重新运行相同命令即可继续。仓库还提供了学习日报提示词，可把文字稿交给大模型进一步整理。

## 准备环境

- Python 3.12 或更高版本。
- uv，用来安装依赖和运行脚本。
- FFmpeg：只有需要从 MP4 提取 MP3 时才需要，安装后将其加入 PATH。

克隆项目并安装依赖：

```powershell
git clone git@github.com:ChuhC/audio_translate.git
cd audio_translate
uv sync
```

首次转写会下载模型，需要联网并等待下载完成；之后可以复用本机缓存的模型。语音识别在本机执行，无需配置转写 API Key。

## 基本用法

建议把自己的文件放到 `data` 目录，例如 `data/video1/课程.mp4`。该目录已被 Git 忽略。

转写 MP4：

```powershell
uv run main.py ".\data\video1\课程.mp4"
```

直接转写 MP3：

```powershell
uv run main.py ".\data\video1\课程.mp3"
```

查看命令帮助：

```powershell
uv run main.py --help
```

脚本每次处理一个文件。路径包含空格时，请用引号包住路径。

输入 MP4 时，如果已有同名 MP3，会直接复用。即使 MP4 已被移走，只要同目录还有同名 MP3，仍可以使用原来的 MP4 命令继续转写。

## 输出与断点续跑

以 `课程.mp4` 为例，生成的文件都位于输入文件旁：

| 文件 | 用途 |
| --- | --- |
| `课程.mp3` | 从视频中提取的音轨；已有时直接复用 |
| `课程.txt` | UTF-8 编码的完整文字稿，每个识别片段占一行 |
| `课程.checkpoint.json` | 已完成的时间点和文本位置，用于续跑 |

转写时，进度条显示已处理的音频时长。可以按 `Ctrl+C` 中断，再执行相同命令，从最近保存的片段继续。续跑仍需要重新加载模型和音频，因此启动时需要等待一会儿。

- 请同时保留 `.txt` 和 `.checkpoint.json`，并避免手动修改转写文本。
- 转写完成后会保留检查点，再次运行会提示已经完成。
- 已有 `.txt` 但没有检查点时，旧文本会备份为 `.txt.bak`；备份已存在则追加编号，然后从头转写。
- 如果音频的大小或修改时间发生变化，脚本会拒绝使用原检查点。需要从头开始时，先移走旧文本和检查点；如果更换的是 MP4，也要移走旧的同名 MP3，才能重新提取音轨。

## 整理学习日报

打开 [视频学习日报提示词](prompts/视频学习日报.md)，填入转写文稿和可选的岗位信息，再交给大模型生成日报。提示词约定了 800–1000 字、3–5 条重点和比较口语化的写法。

日报建议保存为 `原文件名_日报.txt`，与文字稿放在一起。当前脚本只负责转写，日报需要通过提示词单独生成。

## 当前识别设置

`main.py` 使用 `medium` 模型、CPU、`int8` 精度，固定按中文识别，`beam_size=1`。如需调整模型或语言，可修改其中的 `WhisperModel` 和转写参数。

处理速度取决于机器性能和音频长度。人名、专业术语、口音和背景噪声可能影响准确率，整理日报或正式使用前建议核对原文。当前生成的是纯文本，不包含字幕时间轴、说话人区分或翻译；续跑时指定了时间起点，faster-whisper 会忽略 VAD 静音过滤。
